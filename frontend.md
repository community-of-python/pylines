## TypeScript

Для TypeScript необходимо следовать тому набору настроок линтинга, который есть в репозитории. Чаще всего он может меняться.

Также необходимо не допускать prop drilling.

## Стили

Стили необходимо писать с помощью `styled-components`.

При необходимости можно изредка использовать inline-стили в некритичных местах или ради одного правила.

Если пишутся классы, они должны следовать БЭМ-неймингу.

`font-face` использовать нельзя. Все шрифты должны задаваться через `Body` из дизайн системы, который должен оборачивать весь layout.

Стандарт: один `font-face` на весь проект.

Везде, где возможно, нужно брать токены напрямую из дизайн системы. Значения, которые отсутствуют в токенах, нужно класть в настройки проекта.

## React

У `useEffect` желательно должны быть прописаны зависимости.

Все компоненты необходимо писать с использованием хуков.

При объявлении функций в компоненте рекомендуется оборачивать их в `useCallback`.

## Группирование в компонентах

Общий порядок внутри компонента:

1. Список `const` без пустых строк.
2. Пустая строка.
3. Группа `useEffect` без пустых строк.
4. Пустая строка.
5. Разметка `JSX`/`TSX`.

Перед компонентом необходимо делать пустую строку, если перед ним что-то есть: типы, константы, функции и т.п.

## Типы И Приведение Типов

Недопустимо использование кратких инструкций type casting:

- `!!something`
- `~another`
- `+hahaaPrivet`

Типы необходимо приводить явно, без хаков. Явные операции всегда лучше неявных.

## Функции

Функции должны:

- именоваться только глаголами;
- писаться только в виде стрелочных функций: `const doSomething = () => ...`;
- при объявлении внутри компонента по возможности оборачиваться в `useCallback`.

Все магические числа стоит оформлять константами.

## Комментарии

Комментарии лучше не писать почти никогда: они редко несут ценность.

Вместо этого стоит придерживаться принципов самодокументируемого кода: давать семантичные названия функциям, переменным, компонентам, типам и т.п.

Например, переменные `data`, `user`, `request`, `response` — плохие, потому что они не несут конкретного смысла.

Лучше конкретизировать:

- `jsonDataFromKnowledgeBase`
- `userFromKeycloakToken`
- `requestFromSomeService`

Сужение имени до конкретной области — это хорошо. Главное не уходить в гиперспецификацию, когда имя раздувается до неприличных размеров.

## Именование

Имена переменных, функций, компонентов, констант, классов, типов, модулей и всех идентификаторов вообще должны быть не менее 8 символов длиной.

Запрещены слишком общие имена:

- `data`
- `user`
- `variable`

Имена должны быть конкретными, очевидными и понятными без дополнительных пояснений.

Правила регистра:

- переменные и функции: `lowerCamelCase`;
- типы: `UpperCamelCase`;
- константы: `UPPER_CASE`.
